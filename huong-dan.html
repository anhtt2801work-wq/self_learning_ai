Bỏ qua đến nội dung

Cách dùng website này

Trang này hướng dẫn từ việc mở website, đọc và tương tác với bài học, chạy code trong bài, đến chỉnh sửa, thêm bài mới và xuất bản lên mạng. Nếu bạn chỉ muốn học, đọc hai mục đầu là đủ.

1. Mở website

Website là tập hợp file HTML, CSS và JavaScript thuần, không cần cài đặt hay bước build. Có ba cách mở:

CáchLàm thế nàoKhi nào dùng
A. Mở trực tiếp fileTải hoặc git clone repo, nhấp đúp index.html để mở bằng trình duyệt.Nhanh nhất để đọc offline. Mình đã thử với Chromium: bài học, công thức, tìm kiếm và minh họa đều hoạt động khi mở kiểu này. Với trình duyệt khác mình chưa kiểm tra. Nút “Sao chép” code cần ngữ cảnh an toàn của trình duyệt nên có thể không hoạt động ở cách này.
B. Server cục bộTrong thư mục dự án chạy python3 -m http.server 8000 rồi mở http://localhost:8000.Cách khuyên dùng khi bạn sửa bài (giống môi trường thật hơn, nút sao chép hoạt động). Dừng bằng Ctrl+C.
C. Trên mạng (GitHub Pages)Sau khi bật Pages (xem mục 8), mở địa chỉ https://<user>.github.io/<repo>/.Để chia sẻ cho người khác hoặc học trên nhiều máy.

Cần một trình duyệt hiện đại (Chrome, Edge, Firefox, Safari bản gần đây). Website không gọi bất kỳ máy chủ bên ngoài nào khi chạy (KaTeX để hiển thị công thức đã được đóng gói sẵn trong thư mục assets/vendor), nên dùng được khi không có mạng.

2. Điều hướng và phím tắt

  • Thanh tab ở đầu trang chuyển giữa các chủ đề. Trên điện thoại, thanh này cuộn ngang được.
  • Mục lục nằm bên phải mỗi bài (trên màn hình rộng) và tô sáng mục bạn đang đọc. Rê chuột vào tiêu đề để thấy dấu #, bấm vào để lấy liên kết trực tiếp tới mục đó.
  • Cuối mỗi bài có nút Trước / Tiếp theo theo thứ tự lộ trình.
Phím / thao tácTác dụng
/ hoặc Ctrl+K (macOS: ⌘+K)Mở hộp tìm kiếm.
Gõ từ khóaTìm trong tất cả bài, không cần gõ dấu tiếng Việt (gõ “gradient”, “tich chap” đều được). Nhiều từ nghĩa là kết quả phải chứa tất cả các từ.
↑ ↓ rồi EnterChọn và mở kết quả; mở thẳng đến đúng mục.

3. Cách đọc một bài

Mỗi bài có cùng cấu trúc để bạn biết tìm gì ở đâu:

  1. Phần mở đầu và khung “Cần biết trước”: cho biết bài này dựa vào kiến thức nào.
  2. Nội dung chính với công thức, giải thích và đoạn code. Các mục sâu hơn có suy dẫn từng bước, ví dụ số có thể kiểm tra bằng tay hoặc bằng code, sơ đồ SVG, và phần “Đọc nhanh các bài báo/tài liệu nền tảng” tóm tắt ý chính và so sánh phương pháp.
  3. Khung màu: xanh dương là ghi chú, xanh lá là mẹo, cam là cảnh báo (những bẫy hay gặp hoặc điều cần kiểm chứng).
  4. Minh họa tương tác (huy hiệu “Tương tác”) ngay trong dòng chảy bài đọc.
  5. Bài tập: bấm vào tiêu đề để mở lời giải. Hãy tự làm trước khi mở.
  6. Tài liệu tham khảo: nguồn gốc để bạn kiểm chứng và đọc sâu.
Hãy kiểm chứngNội dung được soạn với sự hỗ trợ của AI. Phần tham khảo (tên bài, số arXiv, liên kết) được viết theo trí nhớ và chưa được kiểm tra trực tuyến; mình đã ghi chú ở những chỗ không chắc. Hãy tra lại nguồn trước khi trích dẫn, và với LLM/Agentic AI hãy ưu tiên tài liệu chính thức mới nhất.

Một cách học hiệu quả với website này: đọc một mục, đoán trước điều gì sẽ xảy ra khi đổi một tham số trong minh họa, thử, rồi giải thích vì sao đoán đúng hoặc sai.

5. Chạy code trong bài

Các đoạn code dùng thư viện chuẩn của Python, NumPy, SciPy, scikit-learn, pandas, MLflow, FastAPI hay pytest được chạy thật khi soạn, và các con số in ra được đối chiếu với phần giải thích. Ngoại lệ: đoạn dùng PyTorch, torchvision, transformers hoặc gọi API dịch vụ ngoài chỉ được kiểm tra cú pháp (môi trường soạn bài không cài được hoặc không gọi được chúng), nên hãy chạy thử và đối chiếu với tài liệu của phiên bản bạn cài. Để tự chạy, tạo môi trường ảo và cài thư viện tùy bài:

python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install numpy scikit-learn     # bài Machine Learning, NLP (TF-IDF)
pip install torch torchvision      # bài Deep Learning, Computer Vision (xem pytorch.org để chọn bản phù hợp)
pip install transformers           # bài NLP, LLM
pip install mlflow fastapi uvicorn joblib pytest scipy   # bài MLOps
  • Bài Machine Learning, NLP và MLOps chạy tốt trên CPU. Huấn luyện mô hình lớn (LLM, CNN trên ảnh thật) nên dùng GPU; nếu máy bạn không có, các nền tảng notebook đám mây như Google Colab là một lựa chọn (hãy xem điều khoản và giới hạn hiện hành).

Mật khẩu vào website

Mỗi trang nạp assets/js/gate-config.js và assets/js/gate.js ở <head>; nếu có mật khẩu, trang bị ẩn cho đến khi bạn nhập đúng. Phiên mở khóa được giữ trong tab đang mở (sessionStorage), nên đi qua lại giữa các trang không bị hỏi lại, nhưng đóng tab hoặc mở trình duyệt mới thì hỏi lại.

python3 tools/set_password.py              # nhập mật khẩu mới (không hiện khi gõ)
python3 tools/set_password.py --generate   # sinh mật khẩu ngẫu nhiên, in ra một lần
python3 tools/set_password.py --disable    # tắt cổng
git add assets/js/gate-config.js && git commit -m "Đổi mật khẩu" && git push   # áp dụng trên GitHub Pages

Tệp cấu hình chỉ chứa muối và mã băm PBKDF2-HMAC-SHA256 (150,000 vòng), không chứa mật khẩu. Khi thêm một trang HTML mới, hãy chép đúng hai thẻ <script> của cổng từ một trang có sẵn; tools/check_site.py (và CI) báo lỗi nếu trang nào thiếu.

Giới hạn: đây không phải bảo mật thậtWebsite là các tệp tĩnh. Máy chủ vẫn gửi toàn bộ HTML, JavaScript và chỉ mục tìm kiếm cho bất kỳ ai yêu cầu, và repo đang công khai, nên ai biết xem mã nguồn hoặc mở repo đều đọc được nội dung mà không cần mật khẩu. Cổng chỉ ngăn người vào tình cờ. Mật khẩu yếu còn có thể bị dò từ mã băm công khai (mật khẩu ngẫu nhiên dài từ --generate chống dò tốt hơn nhiều). Muốn giấu nội dung thật sự, cần xác thực phía máy chủ hoặc kho lưu trữ riêng tư; việc dùng GitHub Pages cho repo riêng tư phụ thuộc loại gói của bạn, hãy xem tài liệu GitHub.

Thêm một minh họa tương tác

  1. Trong bài, đặt <div class="viz" data-viz="ten-moi" data-title="Tiêu đề"><p class="viz-help">Gợi ý cách dùng</p></div>.
  2. Trong một file assets/js/viz-*.js, đăng ký: Viz.register('ten-moi', function (root) { ... }). Hàm nhận phần tử root để bạn thêm giao diện vào. Có sẵn các hàm trợ giúp: Viz.mount (canvas tự co giãn, hỗ trợ giao diện tối), Viz.ui.slider / button / select / check / out, Viz.rng (số ngẫu nhiên có seed). Hãy xem các minh họa có sẵn làm mẫu.
  3. Nạp file đó ở cuối trang bằng thẻ <script defer src="assets/js/viz-....js"></script>, sau site.js.
  4. Khởi tạo dữ liệu trước khi gọi Viz.mount, vì khung vẽ gọi hàm vẽ ngay lúc tạo.

Thêm một tab (chủ đề) mới

  1. Sao chép một trang có sẵn (ví dụ mlops.html) làm mẫu, đổi <title>, nội dung và data-page="id-moi" ở thẻ <body>.
  2. Thêm một dòng vào mảng NAV đầu file assets/js/site.js: { id: 'id-moi', href: 'trang-moi.html', label: 'Tên tab', lesson: true }. Thứ tự trong mảng là thứ tự tab và thứ tự nút Trước/Tiếp theo.
  3. Thêm trang vào danh sách PAGES trong tools/build_search_index.py.
  4. Chạy build_search_index.py và check_site.py như trên.

8. Xuất bản lên GitHub Pages

  1. Merge nhánh làm việc vào main (hoặc nhánh mặc định của bạn).
  2. Trên GitHub: Settings → Pages → Source: GitHub Actions. (Tên menu có thể đổi theo thời gian, xem tài liệu GitHub nếu khác.)
  3. Workflow .github/workflows/pages.yml trong repo sẽ tự chạy kiểm tra, đóng gói và triển khai mỗi lần bạn đẩy lên main. Theo dõi ở tab Actions; xong sẽ có địa chỉ https://<user>.github.io/<repo>/.

Mọi liên kết trong website là liên kết tương đối nên chạy được dưới đường dẫn con /<repo>/ mà không cần cấu hình. Gói Pages cho repo private và tên miền riêng phụ thuộc loại tài khoản GitHub của bạn; hãy xem tài liệu GitHub Pages.
